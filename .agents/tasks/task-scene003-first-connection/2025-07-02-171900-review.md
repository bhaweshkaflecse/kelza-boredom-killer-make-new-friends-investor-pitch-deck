# Scene003 — First Connection and relationship architecture

Scene003 introduces the first emotional milestone: two particles discover each other and form a single living filament. The implementation adds a connection state machine (CANDIDATE → PENDING → CONNECTED → DORMANT → BROKEN), a ConnectionManager that orchestrates exactly one connection across a 7-phase emotional timeline (18s), a breathing bezier filament renderer capped at 0.18 opacity / 1.4px width, and a single pulse dot that travels the connection once. The Engine gains a completion-based Scene002→Scene003 transition. Architecture is reusable — state machine, renderer, pulse, and event system are all separable from Scene003 itself.

**Watch for:** Pulse travels along a different bezier than the filament it's drawn on (confirmed). `getCandidateConnections()` allocates a new array every frame during discovery phase (confirmed). Phase timing and ConnectionManager lifecycle run on independent clocks with no synchronization guarantee (likely).

## High-level view

The connection lifecycle is orchestrated by two independent clocks: Scene003Phases drives emotional pacing and environmental callbacks (camera attention, ripple, lighting), while ConnectionManager runs its own phase state machine (DISCOVERY → APPROACH → PAUSE → FILAMENT → PULSE → COMPLETE) on internal elapsed time. The two coordinate only loosely — Scene003Phases adjusts `fieldStrengthMultiplier` and triggers camera/ripple at fixed timestamps, while ConnectionManager operates on particle proximity and its own timers. If ConnectionManager resolves its discovery late (e.g., no candidate pair found within Scene003Phases' Phase 2 window), the scene's emotional cues could fire before or after the connection actually forms.

The PulseRenderer claims to travel along "the same bezier as ConnectionRenderer" but uses the raw midpoint as its control point while ConnectionRenderer displaces the control point with noise. The pulse dot will travel a straight-ish path while the filament curves organically beside it.

The ConnectionPrediction system — originally built for Scene002 — is reused with Scene002's `maxDistance` and `gridCellSize` settings, but Scene003 also defines its own `discoveryRadius` (100px). The two radius values could diverge silently: ConnectionPrediction won't report candidates beyond its `maxDistance` even if Scene003's `discoveryRadius` is larger.

## Pulse/filament bezier divergence

ConnectionRenderer computes its control point as `midpoint + noise_offset` where the noise offset drifts over time (up to ±15px). PulseRenderer sets its control point to the raw midpoint with no displacement:

```js
// ConnectionRenderer
this.cpX = this.midX + noiseOffset;
this.cpY = this.midY - noiseOffset * 0.7;

// PulseRenderer (claims "same bezier as ConnectionRenderer")
this.cpX = this.midX;
this.cpY = this.midY;
```

At 15px displacement the visual gap between the filament curve and the pulse dot's path is noticeable. The comment explicitly claims parity, suggesting this is unintentional rather than a design choice.

## Per-frame allocation during discovery

During the discovery phase (approximately 4 seconds of frames), every `update()` call reaches `getCandidateConnections()` which allocates via `.slice()`:

```js
getCandidateConnections() {
  return this.candidates.slice(0, this.candidateCount);
}
```

The project convention is zero allocations in render/update loops. The early-return guards (`connectionFormed`, `phaseElapsed < discoveryMinTime`) reduce the window, but once `discoveryMinTime` passes and no candidate qualifies, this runs every frame until one does.

## Independent timing clocks

Scene003Phases and ConnectionManager advance on separate elapsed-time accumulators. The phases define fixed timestamps:

```
Phase 4 (Pause): starts at t=11s
Phase 5 (Filament + camera): starts at t=12.5s
Phase 6 (Pulse + ripple): starts at t=14.5s
```

ConnectionManager can only reach FILAMENT after discovery completes (depends on particle positions), approach completes (depends on proximity and force), and pause completes (fixed 1.5s). If the candidate pair is far apart when discovery triggers at t=3s, approach could take the full 4s, pushing CONNECTED to t≈8.5s and FILAMENT to t≈10s — well before Phase 5 fires camera attention at t=12.5s. Conversely, if no candidate is found until t=6s, the cascade pushes PULSE past t=14.5s, and Phase 6's ripple fires before the pulse actually starts.

`beginCameraAttention()` sets a flag that depends on `CONNECTION_STATES.CONNECTED` — if the connection isn't formed yet when Phase 5 fires, the camera attention does nothing until it is. Fail-safe, but emotionally dead: the camera starts attending potentially seconds after the filament appears, or before it.

## ConnectionPrediction reuse and radius coupling

ConnectionPrediction hardcodes its configuration from `settings.scene002.connections`:

```js
const CONN_CONFIG = SCENE002.connections;
// maxDistance, gridCellSize, updateInterval all come from scene002 settings
```

Scene003 creates a new instance but the internal thresholds remain Scene002's. The `discoveryRadius` in `settings.scene003` (100px) is used only by ConnectionManager's `selectBestCandidate` to filter results. If `scene002.connections.maxDistance` is smaller than 100px, ConnectionManager will never find a candidate within its radius because ConnectionPrediction already filtered them out upstream.
