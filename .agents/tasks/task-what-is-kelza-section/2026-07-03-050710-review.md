# "What is Kelza" section for the investor pitch deck

This change adds section 4 to the pitch deck: a concise editorial section answering "What is Kelza?" before any product demonstration. The implementation mirrors the established `MeetKelzaSection` pattern — a CSS stylesheet driven entirely by design tokens, an IntersectionObserver-based controller, and semantic HTML dropped into `index.html` between the "Meet Kelza" section and `</main>`. The section has four parts: a single-sentence definition, a three-pillar concept grid, a text-only ecosystem summary (no SVG duplication), and a bridge sentence into the upcoming live walkthrough.

**Watch for:** The grid jumps from 1-column to 3-columns at 640 px with no intermediate 2-column step (likely uncomfortable on narrow tablets). The `h2` element (`[What Is Kelza]`) uses `--font-size-sm` with uppercase styling, visually demoting the heading to a label while keeping its semantic level — the visual mismatch may confuse sighted users scanning the hierarchy (confirmed).

## High-level view

The three-pillar grid is the only layout decision worth scrutiny: it goes from a single column directly to three columns at 640 px. On a 640-700 px screen, three columns of roughly 180 px each can squeeze pillar text uncomfortably. The prior section (`meet-kelza.css`) doesn't face this because its 640 px breakpoint only adjusts font sizes and padding — it doesn't introduce a multi-column grid at that width.

The `h2` heading is styled as a small uppercase label (`--font-size-sm`) while the `<p>` beneath it carries the dominant visual weight at display scale. This is an intentional editorial pattern ("label above statement"), but it inverts the expected relationship where the semantically primary heading is also the visually largest element.

The JS controller is a line-for-line clone of `MeetKelzaSection.js` with class-name substitutions — same observer config, same lifecycle, same `destroy()` cleanup.

## Pillar grid responsiveness at narrow widths

The pillars grid declares `grid-template-columns: 1fr` by default and jumps to `repeat(3, 1fr)` at `min-width: 640px`. At 640-700 px, each column is roughly 180-200 px. The pillar descriptions ("Find others who share your interests, values, and curiosity through intelligent matching.") are long enough that they'll wrap across 4-5 lines in that width range, creating tall, narrow cards. A `repeat(2, 1fr)` step at 640 px with the 3-column layout reserved for 768 px or wider would distribute text more comfortably without adding complexity.

The prior section's 640 px breakpoint only adjusts font sizes and padding — it doesn't introduce a multi-column grid at that width — so this is a departure from established pattern.

## Heading semantic vs. visual weight

```html
<h2 class="what-is-kelza__heading">[What Is Kelza]</h2>
<p class="what-is-kelza__statement">[One-sentence definition of Kelza]</p>
```

The `h2` receives `font-size: var(--font-size-sm)` with `text-transform: uppercase` and `letter-spacing: var(--letter-spacing-widest)` — styled as a category label. The `<p>` below uses `clamp(var(--font-size-3xl), 4vw + 1rem, var(--font-size-6xl))` — the dominant visual element. Assistive tech will announce the `h2` as the landmark heading, and sighted users will perceive the paragraph as the headline. This inverts the expected visual-semantic relationship where the semantically strongest element is also the visually largest.
